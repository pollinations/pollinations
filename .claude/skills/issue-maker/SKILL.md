# Issue Maker

- Use `pollinations/pollinations`. Check related open and closed issues/PRs, including the latest discussion and close reason, before creating a duplicate or reviving obsolete work.
- Describe the current problem or requested outcome with a short title and up to three concrete bullets. Link related work; use a checklist for tracking issues when useful.
- Follow the user's assignee and label preferences. Otherwise choose the appropriate contributor from current repository context and query existing labels when needed. Root `AGENTS.md` defines app-submission states; do not maintain a separate label list here.
- Return the issue link and a concise summary. Use Discord-compatible formatting when requested.
- Do not create or modify local files for issue-only work.
