# Pollinations GitHub support

For the daily queue scan, read the [Support Git runbook](../../../operations/scheduled-tasks/support-git.md).

Start with the issue, prior replies, relevant documentation, and linked fixes.
Confirm production status before saying a fix is live. Give the operator a short
summary of the confirmed behavior and a draft with a concrete next step. Use
“Pollinations credits” when discussing credit balances.

When a case depends on an individual balance, account, payment or request history,
direct the reporter to private support in the proposed reply. Use the
[email support skill](../pollinations-support-triage/SKILL.md) to verify identity
and investigate the specific case there. Keep account and payment details in the
private support channel.

Follow the operator's authorization before posting or closing an issue. Verify
the result, then continue the next actionable case when the operator has asked
you to work through a queue.
