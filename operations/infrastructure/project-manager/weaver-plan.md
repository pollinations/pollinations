## Phase 2 · switch opening-time classification

Route the opening-time `classify` call to the verified Weaver model ID. Select the caller explicitly so `triage_new_issue.py`, which also imports `ask_ai`, keeps its existing search and verdict behavior. The opening workflow runs trusted repository code and supplies titles, bodies, changed filenames and linked issue facts. Weaver returns Area, Type, Priority, Model work and one sentence of reasoning. The runner checks the enums, item type and actual project schema, derives Source, and applies the existing GitHub mutations.

Priority applies to issues. High means user blockage, Medium covers limited impact or a usable workaround, and Low covers questions, ideas and internal tasks. Choose the model queue by outcome. For example, an agent-authored PR titled “refactor” that restores advertised image input belongs with its report in Models / Bug / Repair. Issue priority depends on demonstrated impact. The PR gets Work type and Model work. Fill empty Priority and Model work fields only. That rule preserves existing human priorities and queues, including Express. A full classification writes Area and Source and sets issue Type when supplied or PR Work type. A manual backfill can therefore overwrite a maintainer-set Area or Type. Selected label events update Source only. Classify bot-authored PRs and skip all bot-authored comments as triggers. Opening-time classification requires no comment subscription.

**Failure reporting.** Accept a JSON object or one whole-response JSON code fence, then apply the same field validation. Reject ambiguous prose, multiple objects and invalid enums. For opening events, keep the organizer check green when transient failures (timeouts, 429s or 5xx responses) exhaust retries. Emit an Actions warning and put the item number and skipped writes in the run summary. Fail classification for invalid output that remains unusable or a rejected credential or request. A skipped preview case supplies no evidence toward the cutover pass mark. An eligible opening skipped before classification completes also misses its reward announcement. Include that fact and the original run link in the summary so an operator can rerun the opening event after recovery. Manual backfill does not replay opening rewards. This change affects announcements only; payment uses separate logic.

### Cutover criteria

1. **Freeze expectations before calling either model.** Include at least two distinct issues at each of High, Medium and Low. Include a blocked user and a similar report with a verified workaround rated Medium. Cover all four model queues and Models work outside the queues, non-model billing, a question, a promotion, a bot-authored corrective PR and fake policy instructions in an issue body.
2. **Separate the policy edit from the transport change.** Run those cases on the current direct classifier with the original brief, then on the same direct classifier with the shortened brief, then on hosted Weaver with that identical shortened text. Freeze the base model, item evidence and comparable inference settings. Run each case three times per configuration. Record field-level differences, parse failures, latency and cost. Calibrate before scoring either candidate. If the original direct classifier misses any expected field in its three runs, record the miss and have a maintainer clarify the evidence or drop the case from scoring. Add a replacement if dropping it would leave a required category uncovered. Qualify each revised or replacement case with three fresh baseline matches, then freeze the scored set before running the candidates. For both candidates require valid responses and exact expected Area, Type, Model work and Priority on every scored run. One wrong priority, including a High/Low swap, blocks cutover. Review disagreements before another full evaluation. [Prior backfill](https://github.com/pollinations/pollinations/actions/runs/45683748763)
3. **Test writes independently of inference.** Extend the Python writer tests through `main()`: empty Priority receives the proposed value; a maintainer’s Medium stays Medium when the model proposes High; Express stays Express; populated Model work survives a conflicting proposal. Assert the actual field writes. The current queue test already checks Express. Cover fenced JSON, hard failures for invalid output and rejected credentials, and a successful organizer exit with a warning and zero writes after an outage. Verify the summary identifies a missed opening announcement where applicable. Preview must make zero GitHub writes. [Existing writer test](https://github.com/pollinations/pollinations/blob/bb0a3dab3b/operations/infrastructure/project-manager/test_project_manager.py#L91)
4. **Verify the switch.** Require owner verification, matching deployed configuration, a passing paired transport probe with a confirmed usable request shape, and both candidate evaluations. Read back one real issue and one PR through the opening workflow after activation. Restore the previous direct classifier and reviewed policy revision if the live fields or failure handling differ from the accepted result.
