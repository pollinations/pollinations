# Weaver · Project Manager

**Decision requested, 27 November 2026.** Approve two steps on the existing #20608 branch. First, register and evaluate one private Pollinations prompt agent called Weaver under `polly@pollinations.ai`. Second, if the evaluation passes, switch the Project Manager’s opening-time classifier to Weaver. The purpose is to run Pollinations’ own project manager as a named hosted agent with its reviewed classification instructions installed. Expect comparable classifications from the same base model. Judge parity against maintainer-reviewed outcomes and measure cost and latency. [PR baseline](https://github.com/pollinations/pollinations/pull/20608)

## Phase 2 · switch opening-time classification

Route the opening-time `classify` call to the verified Weaver model ID. Select the caller explicitly so `triage_new_issue.py`, which also imports `ask_ai`, keeps its existing search and verdict behavior. The opening workflow runs trusted repository code and supplies titles, bodies, changed filenames and linked issue facts. Weaver returns Area, Type, Priority, Model work and one sentence of reasoning. The runner checks the enums, item type and actual project schema, derives Source, and applies the existing GitHub mutations.

Priority applies to issues. High means user blockage, Medium covers limited impact or a usable workaround, and Low covers questions, ideas and internal tasks. Choose the model queue by outcome. For example, an agent-authored PR titled “refactor” that restores advertised image input belongs with its report in Models / Bug / Repair. Issue priority depends on demonstrated impact. The PR gets Work type and Model work. Fill empty Priority and Model work fields only. Preserve Express, human choices, existing special cases and authorized workflow-label behavior. Classify bot-authored PRs and skip all bot-authored comments as triggers. Opening-time classification requires no comment subscription.
